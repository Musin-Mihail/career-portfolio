# Technical Specification: English Tutor AI

## 1. Общее описание проекта

**English Tutor AI** — это веб-приложение для изучения английского языка с использованием генеративного искусственного интеллекта (LLM). Система функционирует как виртуальный репетитор, который генерирует задания на перевод, проверяет ответы пользователя, выставляет оценки, объясняет ошибки и ведет динамический журнал успеваемости.

**Ключевая особенность:** Отсутствие традиционной базы данных. Вся история обучения и профиль студента хранятся и парсятся из локальных Markdown-файлов, что обеспечивает человекочитаемость данных (Human-Readable Data Storage).

**Код:** [github.com/Musin-Mihail/Tool_AI_English_Tutor](https://github.com/Musin-Mihail/Tool_AI_English_Tutor)

## 2. Технологический стек

### Backend (Server-side)

- **Язык:** Python 3.x
- **Фреймворк:** FastAPI (асинхронный веб-сервер).

- **AI Integration:** Google Generative AI SDK (`google-generativeai`). Используемые модели: `gemma-3-27b-it` (или `gemini-3-flash-preview`).

- **Сервер приложений:** Uvicorn (запуск с `reload=True`).

- **Утилиты:** `pydantic` (валидация данных), `python-dotenv` (конфигурация), `re` (RegEx для парсинга файлов).

### Frontend (Client-side)

- **Фреймворк:** Angular (версия ^21.0.0, Modern Standalone Components).

- **Язык:** TypeScript (ES2022 target).

- **State Management:** Angular Signals (`signal`, `update`, `computed`).

- **UI Library:** Angular Material (Material 3 Design).

- **Стилизация:** SCSS.

- **Сборщик:** Angular CLI / Vite (через `@angular/build`).

## 3. Архитектура Backend (`app/`)

Бэкенд построен по модульной архитектуре.

### 3.1. Структура API (`app/api/`)

- **Роутинг:** Реализован через `APIRouter`. Основной эндпоинт `/api/v1/exercises`.
- **Методы:**
- `POST /check`: Принимает перевод студента, возвращает JSON с разбором ошибок, оценкой и исправлением.

- `GET /next`: Генерирует следующее задание на основе контекста ошибок и пробелов в знаниях.

### 3.2. Сервисы (`app/services/`)

1. **`GraderAgent` (AI Logic):**

- Инкапсулирует взаимодействие с LLM.
- Использует **Prompt Engineering** с жестким требованием вывода в формате JSON (без Markdown-оберток).

- **Режим проверки:** Анализирует перевод, классифицирует ошибки (Грамматика, Лексика и т.д.), выставляет балл (0-10), определяет тему.

- **Режим генерации:** Анализирует таблицу успеваемости, находит темы с низким баллом (0.0) и генерирует предложения на русском языке специально под эти темы.

- **Обработка ошибок:** Включает механизмы очистки JSON от лишних символов и fallback-значения при сбоях API.

2. **`FileManager` (Persistence):**

- Отвечает за чтение и запись данных в `.md` файлы.
- **Парсинг:** Использует регулярные выражения (`re`) для извлечения статистики из таблиц Markdown и разделения журнала на блоки заданий.

- **Обновление данных:** Дописывает новые задания в конец журнала и пересчитывает средний балл в таблице успеваемости "на лету".

### 3.3. Модели данных (`app/models/domain.py`)

Используются Pydantic-схемы для типизации запросов и ответов:

- `TranslationRequest`: {`student_translation`, `original_task`}.
- `CheckResponse`: Содержит вложенный словарь результата.
- `GraderResult` (внутренняя модель): Строгая типизация ответа от нейросети (main_topic, score, errors list и т.д.).

### 3.4. Хранение данных (`app/data/`)

- `ENGLISH_performance_table.md`: Содержит профиль студента (уровень A1->B2), активный словарный запас и таблицу оценок по грамматическим темам.

- `ENGLISH_training_journal.md`: Хронологический лог всех заданий, ответов, разборов ошибок и рекомендаций.

## 4. Архитектура Frontend (`src/app/`)

Клиентское приложение представляет собой Single Page Application (SPA) с интерфейсом чата.

### 4.1. Компоненты

- **`App` (Root):** Корневой контейнер с `RouterOutlet`.
- **`ExerciseViewComponent` (Main Feature):**
- Основной экран чата.
- Отображает сообщения двух типов: `teacher` (задания, оценки) и `student` (ответы).

- Поддерживает рендеринг "Карточки оценки" (`evaluation-card`) с цветовой кодировкой баллов (зеленый >= 8, оранжевый < 8) и списком ошибок.

- Реализует индикатор набора текста (`isBusy` signal).

### 4.2. Сервисы

- **`ExerciseService`:**
- Обертка над `HttpClient`.
- Взаимодействует с `http://localhost:8000/api/v1/exercises`.
- Использует RxJS (`Observable`, `firstValueFrom`) для асинхронных операций.

### 4.3. UI/UX Решения

- **Control Flow:** Используется новый синтаксис Angular `@for`, `@if`.

- **Ввод данных:** `MatInput` + `MatButton`. Поддержка отправки по `Ctrl+Enter`.

- **Адаптивность:** Flexbox верстка (`.chat-container`, `.message-row`).

## 5. Поток данных (Workflow)

### Сценарий: Проверка задания

1. Пользователь вводит перевод в Frontend -> `ExerciseService.checkTranslation()`.
2. Backend получает POST запрос. `FileManager` считывает контекст (последние задания и таблицу успеваемости).
3. `GraderAgent` формирует промпт для LLM, включающий:

- Роль (AI-репетитор).
- Текущее задание и ответ студента.
- Список допустимых грамматических тем (Strict Enum).
- Требование вернуть JSON.

4. LLM возвращает анализ.
5. `GraderAgent` валидирует JSON.
6. Если ошибок нет:

- `FileManager` обновляет `ENGLISH_training_journal.md` (добавляет запись).
- `FileManager` парсит `ENGLISH_performance_table.md`, находит нужную тему, добавляет оценку, пересчитывает среднее и перезаписывает файл.

7. Frontend получает JSON и отображает красивую карточку с результатами.

### Сценарий: Новое задание

1. Frontend вызывает `ExerciseService.getNextTask()`.
2. Backend считывает `ENGLISH_performance_table.md`.
3. `GraderAgent` ищет темы с оценкой `0.0` или отсутствующими оценками.

4. LLM генерирует _только_ русское предложение на проблемную тему.
5. Backend возвращает текст задания.
