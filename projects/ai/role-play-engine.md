Проект представляет собой систему для ролевых игр (Role-Play Engine) с использованием локальных LLM (Large Language Models), состоящую из backend-сервера на Python/FastAPI и frontend-клиента на Angular.

# Техническая спецификация проекта Role-Play Engine

## 1. Обзор архитектуры

Система построена по клиент-серверной архитектуре.

- **Backend:** Предоставляет REST API и потоковые данные (SSE) для управления игровым состоянием, обработки ходов с помощью цепочки ИИ-агентов и управления базой данных.
- **Frontend:** Одностраничное приложение (SPA) на Angular, обеспечивающее интерфейс для игры, редактор мира и управление сессиями.

---

## 2. Backend (Server Side)

### Стек технологий

- **Язык:** Python
- **Web-фреймворк:** FastAPI
- **Server:** Uvicorn
- **AI/ML:** `llama-cpp-python` (для запуска локальных GGUF моделей), `openai` (клиентская обертка), `sentence-transformers` (эмбеддинги)
- **Базы данных:**
- **Реляционная:** SQLite (драйвер `aiosqlite`) для хранения сессий, шаблонов и состояния.
- **Векторная:** ChromaDB для долговременной памяти (RAG).
- **ORM:** SQLAlchemy 2.0 (Async).
- **Валидация данных:** Pydantic v2.

### Архитектура ИИ-движка (Multi-Agent System)

Ядром системы является конвейер из специализированных агентов, каждый из которых выполняет узкую задачу. Логика агентов описана в `AGENTS_LOGIC_RU.yaml`.

1.  **Action Validator (Physics Engine):** Проверяет физическую возможность действия игрока с учетом иерархии одежды (Layer 1-3) и наличия предметов .
2.  **Reaction Analyzer (Empathy Engine):** Анализирует действие игрока по шкалам: `urgency` (угроза), `intimacy` (близость), `appropriateness` (уместность) .
3.  **Action Selector:** Выбирает ответное действие NPC на основе анализа реакции, целей персонажа и памяти . Использует RAG для извлечения контекста из ChromaDB.
4.  **Motivation Generator:** Генерирует внутренний монолог, объясняющий причину выбора действия.
5.  **Action Consequence (State Manager):** Преобразует текстовые действия в JSON-обновления состояния мира (изменение инвентаря, снятие одежды) .
6.  **Narrative Planner:** Создает сценарный план (bullet points) для описания хода .
7.  **Story Writer:** Генерирует художественный текст на основе плана . Поддерживает цикл регенерации (Cyclic Regeneration) при ошибках.
8.  **Story Verifier:** QA-агент, проверяющий соответствие текста семантике действий (например, описана ли неудача, если действие провалилось) .
9.  **Chronicle Service:** Создает краткие саммари ходов для истории и векторых баз знаний.

### Модель данных

- **World/Template:** Шаблоны миров, локаций, персонажей и предметов.
- **Session:** Активные игровые сессии.
- **GameState:** Полный слепок состояния, включающий:
- **Scene:** Локация, время, интерактивные объекты.
- **Character:** Состояние, эмоции, цели, инвентарь (массив объектов), одежда (структурированная по слоям: head, torso, legs, underwear и т.д.) .

### Ключевые API Endpoints

- `POST /game/turn`: Обработка хода. Возвращает `StreamingResponse` (Server-Sent Events) для потоковой передачи текста и обновлений статуса.
- `GET /game/state`: Получение текущего JSON-состояния.
- `POST /editor/import/...` & `GET /editor/export/...`: Импорт/экспорт миров и персонажей в JSON .
- CRUD операции для редактора (`/worlds`, `/locations`, `/characters`, `/items`).

## 3. Frontend (Client Side)

### Стек технологий

- **Framework:** Angular 18+ (использует `bootstrapApplication` и Standalone Components).
- **UI Library:** Angular Material (Material 3 Design).
- **Стилизация:** SCSS.
- **Управление состоянием:** Angular Signals (`signal`, `computed`, `effect`).
- **Сборка:** Angular CLI (Vite/Esbuild).

### Структура приложения

Приложение разделено на функциональные модули (Features):

#### 1. Game View (Игровой процесс)

- **GameLoopService:** Управляет циклом обмена данными с бэкендом, поддерживает стриминг ответов через SSE.
- **GameStateView:** Визуализирует JSON-состояние игры (локация, инвентарь, одежда, эмоции персонажа) с использованием табов и чипсов .
- **StoryLog:** Компонент для отображения истории ходов с поддержкой стилизации разных типов сообщений (действия игрока, история, ошибки) и автоскролла .
- **InputArea:** Поле ввода действий с поддержкой горячих клавиш (Ctrl+Enter).
- **Debug Trace:** Панель для просмотра "мыслей" ИИ-агентов (Trace Logic).

#### 2. Editor Dashboard (Редактор мира)

Полноценный CRUD-интерфейс для создания контента:

- **World Editor:** Создание миров.
- **Location Editor:** Настройка локаций, времени суток, интерактивных объектов.
- **Character Editor:** Настройка NPC (характер, цели, инвентарь, сложная система одежды по слоям) .
- **Item Editor:** Создание предметов с динамическими атрибутами (key-value).
- **Import/Export:** Возможность загружать и сохранять JSON-шаблоны .

#### 3. Session Management

- **New Game:** Визард создания новой игры с выбором мира, локации и шаблона персонажа .
- **Session List:** Список сохранений с возможностью загрузки и удаления.

### Особенности реализации

- **Reactive UI:** Использование Signals для реактивного обновления интерфейса при изменении состояния игры (например, `gameState`, `isBusy`).
- **Streaming Support:** Клиент умеет обрабатывать потоковые события `story_chunk`, `progress` (статус агента) и `turn_end` .
- **Responsive Layout:** Использование `MatSidenav` для адаптивной боковой панели с состоянием.

## 4. Системные требования и деплой

- **Запуск Backend:** `python backend/run.py` (хост 127.0.0.1, порт 8001).
- **Запуск Frontend:** `npm start` / `ng serve` (стандартный Angular dev server).
- **Локальная модель:** Требуется наличие GGUF модели (по умолчанию `Mistral-Nemo-Instruct-2407-Q4_K_M.gguf`) в папке `ai_models`.
- **Конфигурация:** Используется `.env` файл для настройки путей и параметров модели.
  Этот проект представляет собой сложную систему, объединяющую классические механики текстовых RPG с современными генеративными моделями, обеспечивая строгую логическую связность (через валидаторы) и богатый нарратив.
