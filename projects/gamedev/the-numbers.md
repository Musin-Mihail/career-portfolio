# Техническая спецификация проекта: "The Numbers" (Unity / Yandex Games)

## 1. Обзор проекта

Проект представляет собой логическую игру-головоломку (вариация механики "Seeds", "Number Match" или "Ten Pair"), разработанную на **Unity (C#)** для платформы **Yandex Games**. Архитектура построена на принципах разделения ответственности, событийно-ориентированном подходе и внедрении зависимостей через Service Locator.

**Код:** [github.com/Musin-Mihail/Game_The_numbers](https://github.com/Musin-Mihail/Game_The_numbers) · **Стора:** [yandex.ru/games/app/451308](https://yandex.ru/games/app/451308)

## 2. Стек и технологии

- **Движок:** Unity (версия совместима с 2021/2022+ на основе синтаксиса).
- **Язык:** C#.
- **Внешние SDK:** Yandex Games SDK (PluginYG / YG2).
- **Сериализация:** `JsonUtility` (Unity) + `Newtonsoft.Json` (для локализации).
- **UI:** Unity uGUI + TextMeshPro.
- **Платформы:** WebGL (ориентация на Yandex Games).

## 3. Архитектура приложения

### 3.1. Паттерны проектирования

- **Service Locator:** Реализован в классе `ServiceProvider`. Используется для регистрации и доступа к глобальным сервисам (`GameEvents`, `GridModel`, `LocalizationManager` и др.).
- **Event-Driven Architecture (EDA):** Взаимодействие между модулями происходит через `ScriptableObject` события (namespace `Core.Events`). Это обеспечивает слабую связность (Decoupling).
- **MVC / MVP:**
- **Model:** `GridModel`, `StatisticsModel`, `ActionCountersModel`.
- **View:** `GridView`, `StatisticsView`, `ActionCountersView`.
- **Controller/Handler:** `GameController`, `MatchHandler`, `HintHandler`.

- **Command Pattern:** Реализован в системе отмены ходов (`Core.UndoSystem`).
- **Object Pooling:** Используется для ячеек сетки (`CellPool`) и всплывающих очков (`FloatingScorePool`).

### 3.2. Точка входа (`GameBootstrap`)

Класс `GameBootstrap` отвечает за:

1. Инициализацию SDK Яндекс Игр (`YG2`).
2. Создание и регистрацию сервисов в `ServiceProvider`.
3. Загрузку сохранений (с механизмом повторных попыток `LoadGameWithRetries`).
4. Проверку миграций данных (например, сброс счета при обновлении версии).
5. Запуск игрового цикла через `GameController`.

## 4. Ключевые системы и логика

### 4.1. Игровая сетка (`GridModel`)

- **Структура данных:** `List<List<CellData>>` (список строк).
- **CellData:** Хранит число, координаты (Line, Column), активность (`IsActive`) и уникальный `Guid`.
- **Оптимизация:** Использует кэширование активных ячеек (`_activeCellsCache`) и флаг `_isCacheDirty` для минимизации пересчета.
- **Механика добавления:** При отсутствии ходов активные числа дублируются и добавляются в конец сетки (`AppendActiveNumbersToGrid`), при этом пустые промежуточные ячейки удаляются.

### 4.2. Логика совпадений (`MatchValidator` & `MatchHandler`)

- **Валидация (`MatchValidator`):**

1. Числа равны ИЛИ их сумма равна 10.
2. Ячейки находятся на одной линии или столбце без препятствий (активных ячеек между ними).
3. Ячейки являются соседями в "линейном" представлении (конец одной строки и начало следующей).

- **Обработка (`MatchHandler`):**

1. Деактивация ячеек.
2. Начисление очков (с учетом множителя).
3. Удаление полностью пустых строк со сдвигом сетки вверх.
4. Запись действия в историю для Undo.

### 4.3. Виртуализация UI (`GridView` & `GridLayoutManager`)

Для оптимизации производительности на больших сетках (до 1000 строк) реализована **виртуализация**:

- Рендерятся только ячейки, попадающие в `ScrollRect` + небольшой буфер (`lineBuffer`).
- `GridLayoutManager` рассчитывает видимый диапазон строк.
- Ячейки берутся из `CellPool` и возвращаются туда при уходе с экрана.
- Позиционирование абсолютное, без использования тяжелых `LayoutGroup`.

### 4.4. Система сохранений (`YandexSaveLoadService`)

- **Провайдер:** `YG2.saves`.
- **Формат данных:**
- **Legacy:** `List<CellDataSerializable>` (старый формат).
- **Compact (Current):** Строка `gridState` формата `col:num,col:num|...`. Пустые разделители `|` обозначают новые строки. Это сделано для обхода лимитов размера сохранений.

- **Данные:** Сетка, статистика (счет, множитель), счетчики действий, настройки (видимость верхней строки), версия миграций.

### 4.5. Система отмены действий (`UndoSystem`)

- Интерфейс `IUndoableAction`.
- Реализация `MatchAction`: Хранит ID ячеек, удаленные линии (полный снапшот удаленной строки) и изменение очков.
- Позволяет восстанавливать удаленные линии и возвращать очки.

## 5. Интеграция с Yandex Games (`Platform`)

### 5.1. Реклама и монетизация

- **Rewarded Ads:** Используется для пополнения счетчиков подсказок и отмены (`RefillCountersRewardId`).
- **Interstitial Ads:** Показываются при добавлении новых линий (`InterstitialAdTimer`).
- **In-App Purchases:** Покупка `disable_counters` отключает лимиты на подсказки и отмену. Обрабатывается в `PlatformBridge` и `ShopManager`.

### 5.2. Таблица лидеров

- Сервис `YandexLeaderboardService`.
- Обновление происходит при каждом изменении рекорда (`LeaderboardUpdater`).
- Отображение (`LeaderboardView`) использует кастомный алгоритм выборки: Топ-3 + Соседи игрока (`LeaderboardDataProcessor`).

## 6. Локализация (`LocalizationManager`)

- Единый JSON файл (`Resources/Localization/translations`).
- Динамическое переключение языка без перезагрузки сцены через события `onSetLanguage`.
- Автоматическое определение языка из среды SDK (`YG2.lang`).
- Поддержка Fallback на английский язык.

## 7. Структура файлов и Namespaces

### Основные Namespaces:

- `Core`: Системная логика, константы, bootstrap.
- `Core.Events`: ScriptableObject события.
- `Model`: Данные (Grid, Stats, Cell).
- `View`: UI компоненты (Grid, Menu, Popups).
- `Gameplay`: Правила игры.
- `DataProviders`: Абстракция доступа к данным для валидаторов.
- `Interfaces`: Контракты для сервисов (DI).

### Важные Editor Tools:

- `ScriptUsageReporter`: Инструмент для поиска использований скриптов на сцене (в папке `Editor`).

## 8. Особенности реализации

1. **Compact Save Format:** Для экономии места в облаке Yandex используется кастомная сериализация сетки в строку, где хранятся только _активные_ ячейки.
2. **Top Line Hint:** Реализован механизм отображения дублирующей верхней строки (`HeaderNumberDisplay`), который помогает игроку видеть числа, ушедшие за верхнюю границу экрана при скролле.
3. **Migration System:** Встроенная система миграций (`seenMigrationIds`) позволяет безопасно обновлять структуру данных или сбрасывать прогресс при обновлении версий игры.
