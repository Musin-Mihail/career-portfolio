# Техническая спецификация проекта "Bobbles" (Unity / C#)

## 1. Общий обзор

Проект представляет собой 2D-казуальную игру-головоломку для мобильных платформ и WebGL (Yandex Games). Основная механика базируется на взаимодействии Drag & Drop и Click, где игроку необходимо сопоставлять объекты с их целевыми местами (тени, контуры, логические пары).

**Код:** [github.com/Musin-Mihail/Game_Unity_Kids](https://github.com/Musin-Mihail/Game_Unity_Kids)

## 2. Стек технологий и зависимости

- **Движок:** Unity.
- **Язык:** C#.
- **Input System:** Unity Input System (используется `PlayerControls`, `PointerPosition`).
- **Внешние SDK:**
- **Yandex Games SDK (YG2):** Сохранения, покупки, инициализация.

- **Unity IAP:** Внутриигровые покупки для Google Play.

- **Платформы:** WebGL (приоритет), Android.

## 3. Архитектура ядра (Core Architecture)

### 3.1. Паттерны проектирования

- **Singleton (Одиночка):** Широко используется для менеджеров. Реализован универсальный класс `Singleton<T>`, обеспечивающий единственность экземпляра и уничтожение дубликатов при загрузке сцен.

- Примеры: `AudioManager`, `Music`, `PurchaseManager`, `WinBobbles`, конкретные менеджеры уровней (`Level1Manager` и т.д.).

- **Inheritance (Наследование):**
- Логика уровней наследуется от абстрактного `BaseLevelManager<T>`.

- Логика спаунеров наследуется от абстрактного `BaseSpawner`.

- **Event-Driven (Событийная модель):** Контроллеры ввода (`DragAndDropController`, `ClickController`) транслируют события (`OnSuccessfulDrop`, `OnObjectClicked`), на которые подписываются менеджеры уровней.

### 3.2. Управление состоянием игры

- **GameConstants:** Статический класс для хранения глобальных констант (скорость движения, дистанция подсказки).

- **Loading & Scene Management:**
- `LoadingSceneBtn`: Загрузка сцен через enum `Options`.

- `StartGame`: Отложенная загрузка сцены выбора уровня.

- **Camera:** Скрипт `CameraAspectRatioMatcher` адаптирует `rect` камеры под целевое соотношение сторон 16:9, добавляя черные полосы (letterboxing) при необходимости.

## 4. Система ввода (Input System)

### 4.1. DragAndDropController

Универсальный контроллер для перетаскивания объектов.

- **Логика:** Raycast 2D по позиции указателя.
- **Слои:** Использует `draggableLayerMask` (слой 13) для захвата и `targetLayerMask` (слой 9) для проверки цели.

- **Валидация:** Поддерживает два типа проверки совпадения: `CheckByName` (по имени) и `CheckByTag` (по тегу).

- **Обратная связь:** Возвращает объект на стартовую позицию при неудаче (`OnDropFailed`) или вызывает событие успеха (`OnSuccessfulDrop`).

### 4.2. ClickController

Контроллер для обработки одиночных кликов (тапов).

- **Логика:** Raycast 2D по слою `clickableLayerMask` (слой 12).

- **Специфичные проверки:** Обрабатывает клики по `BurstingBubble` (лопание пузырей) и `MenuMouse` (UI меню) напрямую, остальные объекты передает через событие `OnObjectClicked`.

## 5. Игровая логика и механики

### 5.1. Менеджеры уровней (`BaseLevelManager`)

Центральный хаб логики для каждой сцены.

- **Обязанности:**
- Инициализация спаунера и подсказок.

- Подписка на события ввода.

- Визуальные эффекты (партиклы успеха/неудачи).

- Аудио-отклик (звук клика).

- **Абстракция:** Предоставляет виртуальные методы `OnSuccessfulDrop`, `OnFailedDrop`, `OnClick` для реализации уникальной логики конкретного уровня.

### 5.2. Система спауна (`BaseSpawner`)

Управляет появлением интерактивных объектов.

- Содержит списки позиций спауна (`startSpawnPositions`, `endSpawnPositions`) и родительский трансформ.

- Реализации (например, `Level1Spawner`, `Level11Spawner`) определяют, как именно создавать объекты (по сетке, последовательно, случайно).

### 5.3. Система подсказок (`Hint`)

Автоматизированная система помощи игроку.

- **Триггер:** Активируется, если игрок бездействует 4 секунды.

- **Визуал:** Объект "Палец" (`finger`) перемещается от активного предмета к его цели.

- **Поиск пары:** Ищет соответствия между списками предметов и целей по имени или тегу.

### 5.4. Условие победы (`WinBobbles`)

- Отслеживает счетчик `victoryCondition`.
- При достижении 0 запускает анимацию (черный фон + партиклы пузырей) и переключает сцену.

- Поддерживает кастомные анимации победы объектов через компонент `WinUp` (подпрыгивание).

## 6. Особенности реализации уровней

- **Уровень 1-9:** Классический Drag & Drop. Животные/объекты перетаскиваются на силуэты.
- _Level 3:_ Многоступенчатая логика (животные -> фигуры).

- _Level 5:_ Механика "Устриц", спаунящих предметы.

- _Level 6:_ Заполнение сундука звездами.

- **Уровень 10 (Scaling):** Механика изменения размера (`Scale`). Спаунер задает случайные масштабы (`scales`) и теги размеров (`sizes`), игрок должен сопоставить размер.

- **Уровень 11 (Grid & Click):** Механика "Наперстки" или поиск. Генерация сетки сундуков, поиск "рыбы" среди пустых сундуков кликами. Логика переключения спрайтов и анимаций.

- **Уровень 12 (Direct Transformation):** Объекты уже на сцене. При клике объект летит к цели и меняет масштаб. Анимация контейнера.

## 7. Монетизация и данные (`Core.Purchase`)

### 7.1. PurchaseManager

Управляет покупкой "No Ads / All Levels".

- **Мультиплатформенность:** Поддерживает `BillingService.Yandex` и `BillingService.GooglePlay`.

- **Сохранение:**
- _Yandex:_ Использует `YG2.saves.allLevelsPurchased`.

- _Google Play:_ Использует `PlayerPrefs` ("AllLevelsPurchased").

- **Инициализация:** Инициализирует Unity IAP для Google Play или подписывается на события YG2.

### 7.2. Защита контента (`Protection`)

- Система блокировки контента (панели, вопросы на русском/английском) для проверки возраста или подтверждения покупки.

## 8. Вспомогательные компоненты

- **MoveItem:** Перемещает объект в заданную позицию (`endPosition`) с заданной скоростью. Используется при спауне для анимации "вылета" предмета.

- **BurstingBubble:** Декоративный элемент. Лопается при клике (смена спрайтов + звук), затем уничтожается.

- **Rotation360:** Простая анимация вращения (используется для звезд и эффектов).

## 9. Замечания для разработки (Refactoring Notes)

1. **LevelDropHandler.cs:** Файл полностью закомментирован. Это легаси-код, функционал которого был перенесен в архитектуру `BaseLevelManager` + `OnSuccessfulDrop`. При генерации кода этот файл следует игнорировать.

2. **Hardcoded Values:** В коде часто встречаются "магические числа" (задержки 0.02f, 4.4f), которые стоит вынести в настройки или константы.
3. **Tags & Layers:** Проект сильно зависит от настройки тегов ("Water", "FishChest") и слоев (12, 13, 9). Это критично для настройки физики и Raycast'ов.
